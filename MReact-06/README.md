## Что сделал

Два фильтра курсов из `courses.json`, каждый в `Panel` из MReact-05. Кнопка «Сбросить» лежит в области `actions`, вне поля ввода.

**Управляемый** (`ControlledFilter`): `<input value={query} onChange={...}>`. Владелец значения — state React. Список фильтруется при каждом вводе. Сброс: `setQuery('')`. React перерисовывает input с пустым `value`, и список снова полный.

**Неуправляемый** (`UncontrolledFilter`): `<input ref={inputRef} defaultValue="">`. Владелец текущего значения — DOM. React задаёт только начальное значение и в ввод не вмешивается. По кнопке «Применить» (или Enter, это submit формы) значение читается через `inputRef.current.value` и сохраняется в `applied`, по нему фильтруется список. Сброс сделан явно: `inputRef.current.value = ''`, `setApplied('')` и фокус обратно в поле. Без строки с `ref` в поле остался бы старый текст: state React его не описывает.

В одном input `value` и `defaultValue` не смешиваются: у первого только `value` + `onChange`, у второго только `defaultValue` + `ref`.

## Почему изменение defaultValue после монтирования не управляет вводом

`defaultValue` — это начальное значение. React кладёт его в DOM-атрибут `value`, а браузер берёт из этого атрибута текст поля только при создании. После этого текущее значение (`input.value`) живёт в DOM отдельно: его меняет пользователь, и React его не перезаписывает, потому что в неуправляемом поле нет `value`, с которым можно было бы сверяться.

Если после монтирования передать новый `defaultValue`, React обновит только атрибут, то есть значение «по умолчанию», а текст в поле останется прежним. Проверка в React 19 (временный компонент, не входит в решение):

| Шаг | prop `defaultValue` | атрибут `value` | текст в поле |
|---|---|---|---|
| монтирование | `first` | `first` | `first` |
| изменили prop, ничего не вводили | `first!` | `first!` | `first` |
| дописали `xyz`, снова изменили prop | `first!!` | `first!!` | `firstxyz` |

Поле не изменилось даже до ввода. Поэтому менять текущий ввод неуправляемого поля можно только императивно через `ref` (как в сбросе здесь) или пересоздав input с новым `key`. А если значением нужно управлять из React постоянно, поле должно быть управляемым.
